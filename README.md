---

## Возможности

### Moodle

| Режим | Описание |
|-------|----------|
| **Палочка (Wand)** | Показывает кнопку рядом с каждым вопросом. Нажмите, чтобы увидеть статистику и выбрать ответ. |
| **Авто-вставка (Auto-Insert)** | Автоматически заполняет ответы на основе статистики сразу при открытии теста. |
| **Авто-прорешивание (Auto-Solve)** | Решает весь тест и автоматически переходит на следующие страницы. |

### OpenEdu

| Режим | Описание |
|-------|----------|
| **Палочка** | Inline-кнопки рядом с каждым вопросом — показывает проверенные ответы и статистику. |
| **Авто-вставка** | Вставляет найденные ответы и подводит к вопросам, где нужен ручной ввод. |
| **Автоматический режим** | Полностью автоматическое решение с авто-переходом между разделами. |

### Дополнительные функции OpenEdu

- Авто-переход после прохождения раздела
- Обновление состояния активного раздела
- Боковая панель со статистикой по всем вопросам
- Резервная статистика (как в Moodle)
- Опциональная проверка ответов в режиме авто-вставки без нажатия «Отправить»
- Если на странице есть неподдерживаемое задание, в меню можно выбрать: решить доступную часть (по умолчанию) или пропустить всю страницу. Неподдерживаемое задание сохраняется в напоминаниях; переход выполняется при включённом авто-переходе.
- Настраиваемая задержка авто-перехода
- Горячие клавиши для показа/скрытия палочки
- Поддержка обычных вопросов, текстовых полей, медиа-вариантов и MatchingTable-задач OpenEdu

## Установка расширения

### Шаг 1: Скачайте расширение

Откройте последний [**GitHub Release**](https://github.com/KOSFin/MooDuSh/releases/latest) и скачайте `moodush-extension.zip`. Распакуйте архив в удобное место.

Для разработки можно клонировать репозиторий:

```bash
git clone https://github.com/KOSFin/MooDuSh-from-syncshare.git
cd MooDuSh-from-syncshare
npm ci
npm run build:extension
```

### Шаг 2: Загрузите в Chrome

1. Откройте `chrome://extensions/`
2. Включите **Режим разработчика** (переключатель в правом верхнем углу)
3. Нажмите **Загрузить распакованное расширение**
4. Выберите папку с файлами MooDuSh (где лежит `manifest.json`)
5. Готово — иконка MooDuSh появится на панели расширений

> **Примечание:** MooDuSh автоматически заменит оригинальное расширение SyncShare, если оно установлено, так как оба используют одинаковые ключи Chrome. Весь функционал SyncShare сохраняется.

## Обновление

Если расширение установлено как unpacked-папка, обновите его внешним скриптом:

```bash
./scripts/update.sh
```

На Windows:

```powershell
.\scripts\update.ps1
```

После обновления откройте `chrome://extensions/` и нажмите кнопку обновления у MooDuSh. Само расширение не перезаписывает свою папку из Chrome — это делает только внешний скрипт, запущенный пользователем.

## Настройка для OpenEdu (пошагово)

Для работы с OpenEdu необходим персональный токен из Telegram-бота.

### Шаг 1: Зарегистрируйтесь в боте

1. Откройте Telegram-бота: **[@paramext_bot](https://t.me/paramext_bot)**
2. Нажмите **Start** или отправьте команду `/start`
3. Бот ответит сообщением с вашим персональным токеном — скопируйте его

### Шаг 2: Настройте расширение

1. Нажмите на иконку MooDuSh на панели Chrome
2. Примите политику в первом экране popup
3. Вставьте токен в поле подключения
4. При необходимости включите **Использовать свой backend** и измените URL
5. Нажмите **Проверить** — статус должен стать **Онлайн**

### Шаг 3: Используйте на сайте

1. Откройте тест на [openedu.ru](https://openedu.ru)
2. Рядом с вопросами появятся кнопки палочки с ответами
3. Выберите подходящий режим в настройках расширения

## Настройка для Moodle

Moodle работает сразу после установки без дополнительной настройки токена.

1. Нажмите на иконку MooDuSh
2. Убедитесь, что выбрана вкладка **Moodle**
3. Выберите режим:
   - **Палочка** — кнопка рядом с каждым вопросом (по умолчанию)
   - **Авто-вставка** — автоматическое заполнение ответов
   - **Авто-прорешивание** — полная автоматизация (нажмите **Старт** для запуска)
4. Настройте горячую клавишу для показа/скрытия палочки (по умолчанию `Escape`)
5. Нажмите **Сохранить**

## Настройки API

В разделе **Настройки API** (кнопка внизу popup) можно настроить подключение к бэкенду отдельно для Moodle и OpenEdu:

## FAQ

**В: Расширение не показывает ответы на OpenEdu**  
О: Проверьте, что вы зарегистрированы в [@paramext_bot](https://t.me/paramext_bot), токен вставлен в настройках API, и статус API — «Онлайн».

**В: Кнопки палочки не появляются**  
О: Убедитесь, что вы находитесь на странице теста. Попробуйте обновить страницу. Проверьте, что палочка не скрыта горячей клавишей.

**В: Как обновить расширение?**  
О: Если скачивали через Git, выполните `./scripts/update.sh`, затем обновите расширение в `chrome://extensions/`.

**В: Как вернуться на оригинальный SyncShare?**  
О: Удалите MooDuSh из `chrome://extensions/` и установите [SyncShare из Chrome Web Store](https://chromewebstore.google.com/detail/syncshare/lngijbnmdkejbgnkakeiapeppbpaapib?hl=ru&utm_source=ext_sidebar).

**В: Авто-прорешивание не переходит на следующую страницу (Moodle)**  
О: Проверьте, что текст кнопки «Далее» в настройках совпадает с текстом на странице (по умолчанию «Следующая страница»).

### OpenEdu: автоматический ChatGPT fallback

В настройках OpenEdu выберите **Авто-прохождение**, затем **Если ответа нет →
Спросить ChatGPT (авто-прохождение)**. Для переходов включите **Переходить к
следующему разделу**. После обновления расширения перезагрузите страницы курса.
Сначала войдите в ChatGPT в этом же профиле браузера.

Расширение открывает собственную вкладку `https://chatgpt.com/`, отправляет
существующий JSON-промпт и возвращается к курсу после ответа. API-ключ OpenAI не
нужен. Не вводите сообщения вручную в эту вкладку во время работы. Содержимое
вопросов, варианты и история неверных ответов передаются в ChatGPT.

Ответы проверяются на полноту и соответствие ключам вопросов, затем применяются
через `requestApplyAnswers` и существующие функции расширения. Отправка выполняется
через внутренний CSRF-aware транспорт CAPA (`postWithPrefix` / `problem_check`),
а результат отображается штатным `Problem` renderer. Панель импорта, буфер обмена
и кнопки расширения для применения ответов не используются. Только транспорт
вкладки ChatGPT работает с его редактором и кнопкой отправки; приватные HTTP API
ChatGPT не используются.

После подтверждённой проверки неверные вопросы с оставшимися попытками отправляются
в ChatGPT повторно вместе с предыдущими ответами. Исчерпанные вопросы исключаются
из следующих запросов. Когда все вопросы решены или попытки исчерпаны, расширение
переходит дальше. Видео и теория распознаются отдельно и пропускаются без запроса
к ИИ; неизвестные или ещё загружающиеся страницы автоматически не пропускаются.

Автоматическая отправка поддерживает стандартные CAPA-проблемы с доступным
`Problem` runtime. Нестандартные виджеты, загрузка файлов и custom-validation
требуют ручной отправки. Ошибки входа, неполный JSON, неопределённая оценка или
неподтверждённая отправка останавливают обработку. Не более 10 раундов на страницу;
для нового запуска после ошибки исправьте её причину и перезагрузите страницу.
Изменения разметки ChatGPT могут потребовать обновления адаптера.

Проверки без внешних сервисов:

```sh
npm ci
npm test
```

Для проверки в браузере используйте тестовый курс: вопрос с одной попыткой,
вопрос с несколькими попытками, смешанную страницу, теорию и видео. Убедитесь,
что после неверного последнего ответа вопрос больше не попадает в промпт,
а обновление страницы во время ожидания ChatGPT не применяет старый ответ.


Во вкладке ChatGPT отображается индикатор MooDuSh: ожидание запроса, ожидание
редактора, отправка и ожидание ответа. Передача промпта теперь подтверждается
самой вкладкой; ранняя загрузка вкладки до сохранения задания не должна приводить
к потере запроса. При отсутствии редактора в течение 30 секунд отображается
явная ошибка вместо молчаливого ожидания.

При вставке промпта сравнивается видимый текст редактора, включая переносы,
представленные HTML-параграфами. Отправка подтверждается новыми сообщениями текущего диалога или очищенным
редактором вместе с начавшейся генерацией; свёрнутый текст промпта не мешает проверке; при ошибке вкладка ChatGPT остаётся открытой с текстом
ошибки.

Если предыдущая неудачная попытка оставила в редакторе тот же промпт MooDuSh с
маркером Request ID, расширение возобновляет его с новым ID. Посторонний черновик
не заменяется: его нужно отправить или перенести перед повторным запуском.

Поддерживается разметка ChatGPT с `data-turn-key`, `data-user-message-bubble` и
`data-chatgpt-agent-turn-start`: сообщения пользователя и помощника учитываются
отдельно, даже если они находятся внутри одного turn. Состояния `cancelled` и
`failed` сообщаются как отмена/ошибка генерации после принятия запроса.

При извлечении JSON исключаются подписи «ChatGPT said:», кнопки и блок запроса
пользователя. Финальный ответ ищется во всём assistant turn, включая соседние с
заголовком блоки. JSON выделяется с учётом вложенных скобок и строк; готовый ответ
без массива `answers` останавливает применение с понятным сообщением.

Вставка checkbox-ответов вызывает нативную активацию изменяемых полей: CAPA
пересчитывает готовность кнопки «Отправить» по событию click. После вставки также
вызывается внутренняя `submitAnswersAndSubmitButton(false)` через main-world bridge;
перед отправкой готовность пересчитывается повторно. Политика исчерпанных попыток
не обходится. Ошибки workflow из iframe показываются на основной странице курса.

Контекст автопрохождения привязан к usage key контейнеров CAPA, а не к изменяемым
отпечаткам вопросов. Обновление UI-настроек и повторная запись тех же настроек
не отменяют запрос к ChatGPT; изменение режима по-прежнему блокирует устаревший
ответ. Перерисованные вопросы после проверки сопоставляются по стабильной ссылке,
а устаревшее сообщение об отмене убирается при возобновлении текущей работы.

В 3.1.10 результат проверки читается также из подтверждённого ответа CAPA:
`current_score`, `total_possible`, `correct_map`. Это позволяет распознавать
полностью верные ответы и нулевой результат даже у виджетов без стандартных
CSS-маркеров. Частичная оценка разбирается по полям, если LMS сообщает их статус;
неопределённая оценка по-прежнему останавливает повторную отправку. Результаты
привязаны к нативному контейнеру задания и именам полей, чтобы перерисовка
таблиц соответствий и текстовых вопросов не теряла подтверждение проверки.

Всплывающие списки ответов открываются только нажатием на значок MooDuSh.
Одновременно открыт один список; нажатие вне него или Escape закрывает его.
Автозаполнение больше не открывает несколько списков при перемещении фокуса.

В 3.1.11 ChatGPT-адаптер читает весь текущий assistant turn, включая финальный
ответ в соседнем блоке за пределами блока состояния. При нескольких новых
сообщениях помощника выбирается последнее в текущем обмене. Пример JSON из
пользовательского промпта по-прежнему исключается.

Автопромпты используют короткие questionKey (`Q3`, `Q5` и т. п.), которые перед
применением преобразуются во внутренние ключи вопросов. Ответ с опечаткой в ID
может быть сопоставлен по index только если все выбранные варианты однозначно
соответствуют одному запрошенному вопросу. Для произвольного текстового ответа
или неоднозначного набора вариантов такого сопоставления нет. В ошибках указаны
неизвестные, повторные или пропущенные ID вместо общего «unrelated answers».
После обновления расширения нужно перезагрузить и OpenEdu, и управляемую вкладку
ChatGPT, чтобы обе стороны использовали новый код.

В 3.1.12 удалено преждевременное завершение через 10 секунд без JSON:
промежуточный блок размышления или placeholder с completed не считается
финальным ответом. Адаптер ожидает результат до 180 секунд после подтверждения
отправки. Ответ читается только после пользовательского сообщения текущего
запроса; предыдущие сообщения без этой привязки не завершают запрос.

В 3.1.13 ожидание ответа ChatGPT увеличено до 10 минут после подтверждённой
отправки промпта. Резервирование задания в background действует 12 минут
с учётом загрузки вкладки и подготовки отправки; OpenEdu ждёт результат
до 12 минут 5 секунд. Долгий ответ не теряется из-за прежних более коротких
таймеров и не позволяет другому iframe перезаписать активное задание.

В 3.1.14 тайм-аут ответа ChatGPT настраивается в popup → OpenEdu:
«Тайм-аут ответа ChatGPT, мин». Диапазон 1–60 минут, по умолчанию 10.
Настройка сохраняется и применяется к следующим запросам. Текущий запрос
сохраняет выбранное при старте значение, в том числе после перезапуска MV3 worker.
Время резервирования задания равно выбранному тайм-ауту + 2 минуты для загрузки
вкладки и подготовки отправки; OpenEdu добавляет ещё 5 секунд для доставки
результата. Эти служебные интервалы рассчитываются автоматически.

В 3.1.15 пропущенные вопросы и пустые массивы answers обрабатываются отдельно:
расширение сохраняет остальные проверенные по формату ответы и запрашивает
только недостающие вопросы, не более двух дополнительных запросов. До получения
полного набора ответы не применяются и попытки OpenEdu не тратятся. Если ИИ
снова оставляет вопросы пустыми, ошибка перечисляет их Q-номера. Промпт явно
запрещает пустые answers. При ошибке применения указаны номер, тип и начало
текста вопроса; статус показывает текущий этап применения.

Исправлена доставка следующего промпта, если ChatGPT-адаптер ещё освобождает
предыдущее задание: background повторяет доставку, сохраняя ID запроса.

В 3.1.16 текстовые вопросы экспортируются в AI с контекстом всего текущего
задания CAPA, включая предложения до и после поля. Целевые поля помечаются
[ANSWER N], остальные пропуски — [BLANK N]. Это исправляет экспорт только
инструкции «Вставьте пропущенное слово» и потерю текста между элементами HTML.
Из контекста исключаются элементы MooDuSh, текущие значения полей, кнопки и
сообщения проверки; соседние задания не добавляются. Ключи вопросов и исходный
парсер не меняются: расширенный контекст используется только в AI-экспорте.
Работа с изображениями в этом обновлении не изменялась.

## Снимок всей страницы для ChatGPT

Перед каждым автоматическим запросом, включая исправление ответов, расширение
снимает всю текущую страницу курса: по всей ширине и высоте, включая содержимое
ниже видимой области. Области соединяются в полный снимок в исходном разрешении экрана, без уменьшения
и JPEG-сжатия. Снимок помещается в `openedu-full-page.pdf`: последовательные
страницы PDF сохраняют все исходные пиксели и порядок содержимого. Перед съёмкой страница
прокручивается для загрузки изображений; после съёмки прокрутка восстанавливается.
Поддерживаются вложенные фреймы разных доменов OpenEdu.

PDF и список вопросов отправляются одним сообщением. Промпт предлагает найти
на страницах PDF недостающие условия, рисунки, графики, формулы и варианты ответа.
Ответ должен содержать полный JSON ответов. Отдельных запросов снимков от модели,
этапа ожидания снимков и счётчика повторных запросов больше нет.

Ошибки съёмки или неподтверждённые вложения останавливают запрос без применения
ответов. При превышении ёмкости canvas или лимита передачи PDF (48 MB до base64)
расширение сообщает об ошибке, не отправляя обрезанный или уменьшенный снимок.
Для автоматической съёмки используется `<all_urls>` и `captureVisibleTab`.
После обновления перезагрузите расширение и вкладки курса и ChatGPT.

Большие промпты (более 12 000 символов) передаются в rich-text редактор
ChatGPT файлом `.txt` с короткой инструкцией в поле сообщения. Полный текст
запроса сохраняется; PDF всей страницы прикладывается вместе с текстовым файлом.
Это позволяет не вставлять тысячи строк JSON в редактор страницы.
Загрузчик использует общий файловый input текущего поля сообщения и проверяет,
обработал ли ChatGPT выбор файла. Если редактор заменил input или обработчик
ещё не подключён, выбор повторяется в течение ограниченного времени. Видимое
вложение по-прежнему обязательно для отправки запроса.

При перезагрузке вкладки ChatGPT расширение возобновляет неотправленный
запрос либо продолжает ждать ответ на уже отправленный. Если отправленный
запрос не найден в открытом разговоре, расширение сообщает об этом и
останавливается, не отправляя его повторно.

## Напоминания о заданиях OpenEdu, требующих ручного выполнения

Когда MooDuSh встречает интерактивное задание, которое не умеет решать
(например, диалоговый JSInput-тренажёр), он сохраняет
чистую ссылку в локальном хранилище расширения. Видео, теория и поддерживаемые
вопросы не вызывают напоминаний.

При добавлении нового задания расширение создаёт фоновую вкладку
«MooDuSh — Напоминания» или обновляет уже открытую. Текущая вкладка остаётся
активной. Повторные посещения не добавляют дубликаты. Список сохраняется после
закрытия вкладки и перезапуска браузера.

Открыть список можно кнопкой «Напоминания» в шапке popup расширения.
Сообщения поверх страницы курса не показываются. В автоматическом режиме
с включённым переходом между разделами MooDuSh продолжает дальше после
сохранения ссылки, даже если тренажёр не отмечен выполненным. Поддерживаемые
вопросы в том же разделе сначала должны быть решены. В списке можно перейти к заданию и
убрать ссылку, когда она больше не нужна. Повторное обнаружение убранного
задания добавит его снова.

Отдельные файлы, локальные помощники и дополнительные разрешения браузера
не требуются. Ранее сохранённые расширением ссылки доступны в том же списке.
